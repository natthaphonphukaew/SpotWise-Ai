## 1. Positioning

**SpotWise AI = Explainable AI ช่วยเลือกทำเลเปิดร้าน ที่ "รู้ว่าตัวเองไม่รู้อะไร" แล้วพาผู้ใช้ไปเก็บข้อมูลที่ขาด**

- ไม่ใช่เว็บแผนที่ + แชตบอต และไม่อ้างว่าทำนายยอดขายได้แม่นยำ
- ทุกตัวเลขมีที่มา (Evidence) และระดับความเชื่อมั่น (Confidence)
- จุดต่างที่คนทำน้อย: **Confidence ที่เพิ่มขึ้นได้จริง** เมื่อผู้ใช้ลงพื้นที่ (Field Mode) และ **ความเสี่ยงช่วงปิดเทอม** ซึ่งเป็นปัญหาจริงของร้านรอบมหาลัย

### คำถามเดียวที่ระบบต้องตอบให้ดี
> "ถ้าจะเปิดร้านชาไข่มุก 40–60 บาท ขายนักศึกษา มจธ. ทำเล A, B, C แห่งไหนดีที่สุดสำหรับงบของฉัน — เพราะอะไร เสี่ยงตรงไหน และต้องไปเช็กอะไรเพิ่มก่อนเซ็นสัญญา?"

### ขอบเขตเดโม (ล็อกไว้)
- พื้นที่: รัศมี ~2 กม. รอบ มจธ. บางมด (ประชาอุทิศ, พุทธบูชา, สุขสวัสดิ์ช่วงบางมด)
- ประเภทธุรกิจ: **ร้านชาไข่มุก** และ **ร้านกาแฟ** (มี template สำเร็จรูป)
- ทำเลผู้สมัคร: 6–10 จุดจริงที่เดินสำรวจ (อาคารพาณิชย์ "ให้เช่า" พร้อมค่าเช่าจริง) + ปักหมุดเองได้

## 2. AI ทำอะไรในระบบ (คำตอบของ "AI อยู่ตรงไหน")

| # | บทบาท | ชนิด | ทำไมต้องเป็น AI |
|---|---|---|---|
| 1 | **Business Profiler** — ข้อความภาษาคน → profile JSON (หมวดคู่แข่งตรง/อ้อม, สถานที่เกื้อหนุน, ช่วงเวลาขาย, ราคาต่อบิล, น้ำหนักคะแนน) | LLM + structured output | ต้องใช้ความรู้เชิงธุรกิจ เขียนกฎเองไม่ครอบคลุม |
| 2 | **POI Relevance Classifier** — ตัดสินทีละร้านว่าเป็น คู่แข่งตรง / คู่แข่งอ้อม / เกื้อหนุน / ไม่เกี่ยว พร้อมเหตุผล | LLM (batch, cache) | หมวดของข้อมูลเปิดสกปรก เช่น ร้านกาแฟในปั๊มนับไหม |
| 3 | **Demand Estimator** — ลูกค้าคาดการณ์/วัน แบบช่วง ต่ำ/กลาง/สูง | Huff Gravity Model (คณิตศาสตร์ อธิบายได้) | ปิดช่องว่างที่ผู้ใช้ไม่รู้ว่าจะได้ลูกค้ากี่คน |
| 4 | **Storefront Vision Check** — ถ่ายรูปหน้าร้าน → ประเมินการมองเห็น ที่จอดมอไซค์ ทางเท้า ร่มเงา ป้าย | LLM Vision | วิเคราะห์ภาพที่ผู้ใช้ถ่ายเอง |
| 5 | **Grounded Advisor** — รายงานสรุปที่อ้าง evidence ID ทุกข้อ แยก ข้อเท็จจริง / สมมติฐาน / ข้อเสนอแนะ | LLM + ตรวจ citation อัตโนมัติ | วัด hallucination rate ได้ |
| 6 | **Devil's Advocate** — AI ฝ่ายหนุน vs ฝ่ายค้าน ถกกันจาก evidence ชุดเดียวกัน แล้วสรุป | LLM multi-call | ทำให้เห็นมุมเสี่ยงที่ผู้ใช้มองข้าม |

> หลักการ: **AI เข้าใจ คัดกรอง และให้เหตุผล — ตัวเลขมาจากโมเดลที่ตรวจสอบได้**

## 3. Core Pipeline

```
[ข้อความคอนเซ็ปต์ร้าน + ทำเล A/B/C + ค่าเช่า + งบ]
   ① LLM → Business Profile (ผู้ใช้ยืนยัน/แก้ได้)
   ② Catchment: isochrone เดิน 5/10 นาที (precompute) หรือรัศมีเส้นตรง (custom pin, ระบุว่าเป็นค่าประมาณ)
   ③ ดึงข้อมูลจาก cache ย่านบางมด: POI, ประชากรกริด, ป้ายรถ/ถนน, สถานศึกษา
   ④ LLM จัดประเภท POI
   ⑤ ตัวชี้วัด + Huff → ลูกค้า/วัน (ช่วง)
   ⑥ Loc-Score + Confidence + Evidence
   ⑦ Scenario Simulator + Term-Break Cashflow 12 เดือน
   ⑧ Grounded Advisor (+ Devil's Advocate) → "สิ่งที่ต้องเช็กเองก่อนเซ็นสัญญา"
   ⑨ Field Mode: ผู้ใช้ลงพื้นที่ → ข้อมูลจริงแทนค่าประมาณ → Confidence เพิ่ม → คะแนนคำนวณใหม่
```

## 4. Loc-Score

| มิติ | วิธีวัด | แหล่ง | น้ำหนักเริ่มต้น (ชาไข่มุก) |
|---|---|---|---|
| ความเหมาะกับกลุ่มเป้าหมาย | ประชากร/นักศึกษาใน catchment × ความตรงกับ persona | WorldPop + จำนวนนักศึกษา มจธ. | 25% |
| การเข้าถึง/กิจกรรม | ป้ายรถ/วินมอไซค์, ถนนหลัก, ความหนาแน่น POI, activity profile | OSM + Overture | 20% |
| ความอิ่มตัวของตลาด | **คู่แข่งต่อดีมานด์** (ไม่ใช่นับจำนวนร้านเฉยๆ) | ผลจาก Huff | 20% |
| ความคุ้มค่าค่าเช่า | **ค่าเช่า ÷ รายได้คาดการณ์** (เกณฑ์ทั่วไป ร้านอาหารไม่ควรเกิน ~10–15%) | ผู้ใช้กรอก + ⑤ | 20% |
| สถานที่เกื้อหนุน | จำนวน + ระยะของ anchor (มหาลัย หอพัก ตลาด ออฟฟิศ) | POI | 15% |

- **Confidence** ต่อมิติ = f(ความครบ, ความสด, แหล่งข้อมูล: เดินสำรวจจริง > ข้อมูลเปิด > ค่าประมาณ)
- ผู้ใช้ปรับน้ำหนักด้วย slider และเห็นคะแนนเปลี่ยนทันที
- **ห้าม** แสดงคะแนนเป็น "% โอกาสรอด"
- Huff (เวอร์ชันง่าย): `P(ร้าน j) = (A_j / d^λ) / Σ_k (A_k / d^λ)` · demand point = กริดประชากร + หอพัก + มหาลัย · `ลูกค้า/วัน = Σ ประชากร × อัตราซื้อต่อวัน (สมมติฐาน) × P` ให้ผลเป็นช่วง ไม่ใช่ค่าเดียว

## 5. Wow Features (ตัวที่คนทำน้อย)

### W1 · Term-Break Cashflow — **Must**
กระแสเงินสด 12 เดือน ที่ดีมานด์ลดลงช่วงปิดเทอม/สอบ ตามปฏิทิน มจธ. จริง
- ข้อความตัวอย่าง: "ปิดเทอม มิ.ย.–ก.ค. ลูกค้าหาย ~60% ต้องมีเงินสำรอง 2 เดือนค่าเช่า"
- ข้อมูล: [ปฏิทินการศึกษา มจธ. 2569](https://regis.kmutt.ac.th/calendar/AcademicCalendar2026-2569TH.pdf) (ต้องกรอกวันเปิด-ปิดภาคเอง) · ตัวคูณดีมานด์ช่วงปิดเทอมเป็นสมมติฐานที่ผู้ใช้ปรับได้ และควรยืนยันด้วยการคุยกับเจ้าของร้านแถวนั้น 2–3 ร้าน

### W2 · Field Mode (มือถือ) — **Must** ← หัวใจของเรื่องเล่า
"AI บอกว่ายังไม่รู้อะไร แล้วพาไปเก็บ"
- **Footfall Tap Counter:** ยืนหน้าทำเล กดนับคนเดินผ่าน 10 นาที แยกตามช่วงเวลา
- **Storefront Photo Check:** ถ่ายรูปหน้าร้าน → Vision AI ประเมิน checklist
- **Rent & Notes:** กรอกค่าเช่าจริง ค่ามัดจำ หมายเหตุ
- ผล: มิติที่เกี่ยวข้องเปลี่ยนจาก "ประมาณ" เป็น "สำรวจจริง" **Confidence เพิ่มขึ้นแบบมี animation** และคะแนนคำนวณใหม่

### W3 · Devil's Advocate — **Should**
แสดงเป็นบทสนทนา 2 ฝั่ง แต่ละข้อมี citation แล้วจบด้วยคำตัดสิน + เงื่อนไข "จะเปลี่ยนใจถ้า…"

### W4 · Spot Finder Heatmap — **Should**
พิมพ์คอนเซ็ปต์แล้วทั้งย่านเปลี่ยนสีตามคะแนน (กริด ~50 ม. คำนวณฝั่ง client จากข้อมูล cache) ใช้ปิดเดโม: "จุดที่ดีที่สุดอาจไม่ใช่ 3 จุดที่คุณเลือกมา"

## 7. หน้าจอ

1. **Setup** — พิมพ์คอนเซ็ปต์ → AI แสดง profile เป็นการ์ดที่แก้ได้ → เลือก/ปักทำเล 3 จุด
2. **Map** — แผนที่เต็มจอ + คอลัมน์รายงานด้านซ้าย · catchment · POI (คู่แข่ง/เกื้อหนุน) · แถบเวลา เช้า→ค่ำ
3. **Compare** — ตารางเทียบ 5 มิติ (เส้นบาง สไตล์สิ่งพิมพ์) · คลิกเปิด Evidence · Confidence badge · slider น้ำหนัก
4. **Simulate** — 3 สถานการณ์ + กราฟเงินสด 12 เดือนที่เห็นหลุมปิดเทอม
5. **Advisor** — รายงาน + เชิงอรรถ [1][2] ที่คลิกไปหา evidence ได้ · Devil's Advocate · checklist ก่อนเซ็นสัญญา
6. **Field Mode** (mobile) — ปุ่มนับคนขนาดใหญ่ · กล้อง · ฟอร์มค่าเช่า

## 8. Tech Stack (ฟรีล้วน, เหมาะกับทำคนเดียว)

**ตัดสินใจ: Next.js ตัวเดียว + Python เฉพาะ data pipeline แบบ offline** (ไม่มี backend Python ให้ต้อง host)

| ส่วน | เลือก | หมายเหตุ |
|---|---|---|
| Web app | Next.js (App Router) + TypeScript + Tailwind (ใช้ token ของเราเอง) | deploy บน Vercel Hobby |
| แผนที่ | MapLibre GL JS + basemap จาก OpenFreeMap หรือ Protomaps (ปรับสีให้เข้ากับแบรนด์) | ไม่ต้องใช้ API key · ต้องแสดง attribution ของ OSM |
| Geo บน client | Turf.js | รัศมี, point-in-polygon, กริด W4 |
| กราฟ | Observable Plot หรือ D3/SVG เขียนเอง | ห้ามใช้หน้าตา default ของ chart lib |
| LLM | adapter สลับ provider ได้: **Gemini (free tier) เป็นหลัก** → Groq / OpenRouter free models สำรอง | structured output + zod · **cache ทุกผลลัพธ์** ตาม hash ของ input |
| Data pipeline | Python (uv) + `overturemaps` CLI + DuckDB + OSMnx + geopandas + rasterio | output เป็น GeoJSON/JSON ใน `public/data/bangmod/` |
| Storage | ไฟล์ JSON แบบ static + localStorage (ข้อมูล Field Mode) | ยังไม่ต้องมี DB |

### แหล่งข้อมูลฟรี

| ข้อมูล | แหล่ง | license / ข้อควรระวัง |
|---|---|---|
| POI หลัก | [Overture Maps Places](https://docs.overturemaps.org/guides/places) | CDLA-Permissive / Apache / CC0 · โหลดเฉพาะ bbox ได้ |
| POI เสริม | [Foursquare OS Places](https://foursquare.com/resources/blog/products/foursquare-open-source-places-a-new-foundational-dataset-for-the-geospatial-community/) | Apache 2.0 · ต้องลงทะเบียนเพื่อรับ token |
| ถนน / ป้ายรถ / อาคาร / เครือข่ายทางเดิน | OpenStreetMap (Overpass, OSMnx) | ODbL ต้องแสดง attribution |
| ประชากรแบบกริด | WorldPop / Meta High-Resolution Population | ฟรี |
| จำนวนนักศึกษา / ปฏิทินการศึกษา | เว็บ มจธ. / สถิติ อว. | กรอกเอง |
| ค่าเช่า | **เดินสำรวจเอง** | ข้อมูลจริง = จุดแข็งของเรื่องเล่า |
| ข้อมูลจาก Google Maps | ❌ ไม่ใช้ | ToS ห้ามคัดลอก และไม่ฟรี |

> ⚠️ free tier ของ Gemini: โควตาไม่แน่นอน (เปลี่ยนบ่อย ดูใน AI Studio) และข้อมูลอาจถูกนำไปปรับปรุงโมเดล → ห้ามส่งข้อมูลส่วนบุคคล และ **ผล LLM ของเดโมต้อง pre-generate และ cache ไว้ทั้งหมด**

## 9. การพิสูจน์ว่า AI มีประโยชน์ (หน้า Validation)

1. **ความครอบคลุมของข้อมูลฟรี:** เดินสำรวจถนน 2–3 เส้นรอบ มจธ. เทียบกับ Overture/FSQ/OSM ว่าเจอร้านจริงกี่ % (ผลนี้เป็น finding ได้ในตัว)
2. **ความแม่นของ POI Classifier:** label เอง 100 ร้าน เทียบ precision/recall ระหว่าง "หมวดดิบ" กับ "LLM จัด"
3. **Monotonicity tests:** ค่าเช่าขึ้น คะแนนต้องลง คู่แข่งเพิ่ม (ดีมานด์คงที่) คะแนนต้องลง → เขียนเป็น unit test
4. **Grounding rate:** % ของประโยคในรายงานที่อ้าง evidence ถูกต้อง เป้าหมายเกิน 95%
5. **Chain Backtest:** สาขาของแบรนด์เชน (ชาไข่มุก/กาแฟ) ในโซนฝั่งธนฯ ใต้ ได้คะแนนสูงกว่าจุดสุ่มไหม (AUC) และต้องตัดร้านตัวเองออกจากการนับคู่แข่ง

## 10. Demo Script (3 นาที)

1. **0:00 Hook** — "ร้านรอบมหาลัยเจ๊งเพราะอะไร? ไม่ใช่แค่ทำเล แต่เพราะปิดเทอม"
2. **0:20 Setup** — พิมพ์คอนเซ็ปต์ร้าน → AI แตกเป็น profile → เลือก 3 ทำเลรอบ มจธ.
3. **0:50 Map + Compare** — คลิกคะแนนเห็น evidence และ Confidence ต่ำในมิติ footfall
4. **1:30 Simulate** — ลากค่าเช่า กราฟเงินสดเห็นหลุมปิดเทอม → ทำเล B ที่ดูดีกลับเสี่ยงเงินสดขาด
5. **2:00 Field Mode** — เปิดมือถือ ใส่ผลนับคนจริงและรูปหน้าร้านที่บันทึกไว้ → Confidence เพิ่ม อันดับเปลี่ยน
6. **2:30 Advisor + Devil's Advocate** — สรุปพร้อมเชิงอรรถ + checklist ก่อนเซ็นสัญญา
7. **2:50 Spot Finder** — ทั้งย่านเปลี่ยนสี "จุดที่ดีที่สุดอาจไม่อยู่ในลิสต์ของคุณ"
